# 去AI味写作指南

> ⚠️ 所有检测阈值以 `novel-config.json` → `ai_flavor` 为准。以下数值均为默认值，AI 自检时先读取 config 覆盖。

## 使用路由

- 阶段 B 硬性检查读“Grep 可检测的AI味”。
- 软性读感问题读“句式/段落/对话自然度”。
- 需要重写判断时读“阶段 B 一次过 vs 重写”。

## 为什么AI味是长篇小说的头号杀手

AI写作的核心问题不是"写得差"，而是**模式重复**。单章看没问题，50章累积之后：
- 每章的句式结构都一样
- 每场战斗都用同一套动词
- 每个角色的情绪都是"一股XX涌上心头"
- 每段对话都是 "A说→B回应→A再回应" 的均匀节奏

**读者可能说不出为什么，但会觉得"腻"**。

## 一、硬性模式：Grep 可检测的AI味

### 1.1 高频过渡词

| AI常用 | 问题 | 替换方向 |
|--------|------|---------|
| 随后 / 接着 / 然后 | 三段内出现两次以上就显得机械 | 有时直接省略更好；或用具体动作过渡 |
| 与此同时 | 滥用导致毫无"同时感" | 大部分场景不需要这个连接词 |
| 不仅如此 | 假递进，后面跟的内容往往不值得强调 | 删掉或换成具体描述 |
| 更为重要的是 | 同上 | 如果真的很重要，写法上就该体现出来，不需要喊 |

### 1.2 模板化情感表达

| AI常用 | 问题 | 替换方向 |
|--------|------|---------|
| 一股XX涌上心头 | 网文最泛滥的情感模板 | 换成具体身体反应：（握紧的拳头/加速的心跳/屏住的呼吸）|
| 眼中闪过一丝XX | 千篇一律 | 换成具体的眼神变化描述，或省略 |
| 他感到/他意识到/他明白 | 说教式——告诉读者而不是让读者感受 | 删掉这层概括，让前面的描写自己说话 |
| 心中一惊/心中一凛/心中一沉 | 用烂了 | 换成具体的情境反应 |

### 1.3 形容词堆砌

| AI常用 | 问题 | 替换方向 |
|--------|------|---------|
| 无比 + 形容词 | 假强调 | 换成具体的程度描写 |
| XX至极 / XX到了极点 | 偷懒 | 换成可感知的细节 |
| 强大无比的力量 | 什么都没说 | "力量"换成有画面感的描写 |

### 1.4 过渡解释

```
AI常用：林夜之所以选择剑冢，是因为他需要借助剑气的压力来突破瓶颈。

真人写法：剑冢的剑气，是天然的磨刀石。林夜需要一块磨刀石。
（"之所以/是因为"这种解释句式在网文中几乎永远可以删掉重写）
```

## 二、软性模式：需要"耳朵"检测的AI味

### 2.1 句式单调

**问题**：全章每句话都在15-25字之间，没有句子长度的起伏。

**检查方法**：朗读本章前500字。有2-3字的短句吗？有30字以上的长句吗？

**真人写作**：
```
三息。只有三息。
剑冢深处的剑气从四面八方涌来，像有一万把无形的刀刃同时压向他的身体。林夜没有退，反而向前踏了一步。
血。
```
（2字→30字→19字→2字——节奏分明）

**AI写作**：
```
剑冢深处的剑气从四面八方涌来。林夜感到巨大的压力落在身上。他深吸一口气，向前踏出一步。
```
（12字→14字→13字——全是中句）

### 2.2 段落结构单一

**问题**：每段3-4句，章节像豆腐块一样均匀排列。

**检查方法**：拉开距离看章节的段落轮廓。有单句段吗？有超过5行的长段吗？

### 2.3 人物语气趋同

**问题**：第50章时，所有人的说话方式都变得差不多——冷静、讲道理、句式完整。

**检查方法**：遮住名字，能分辨出谁在说话吗？

**维护方法**：每个主要人物设定1个"语言指纹"：
- 句长偏好：A说话不超过10字 / B喜欢长句解释
- 口头禅/标志词：但不能滥用（每3-5章出现1次即可）
- 停顿习惯：某人在紧张时会结巴/沉默/重复某个词
- 独特视角：某人总是从利益角度看问题，某人总是先关心人

### 2.4 描写套路化

**问题**：同样的描写框架在不同章节重复出现。

**检查方法**：对比5个不同章节的环境描写开头。如果用同一套模板（"时间+光线+风+主角反应"），就是AI味。

**真人写作**：每次环境描写有独特的"入点"——可能是声音、气味、温度，而不总是视觉。

### 2.5 情绪"说"而非"演"

**问题**：人物情绪通过概括句传达（"他感到愤怒"），而非通过行为、对话、身体反应。

```
AI写法：看到赵明的瞬间，林夜心中涌起一股愤怒。

真人写法：林夜没有说话。他握着剑柄的手指一根一根收紧，指节发白。
```

## 三、网文特有的风格要求

### 3.1 不完美反而更"真"

允许存在：
- 口语化、不符合文法的句子（"这特么就离谱"）
- 网络热梗和流行语（适度使用，符合角色设定）
- 不完整的段落（战斗场景中尤其需要）
- 留白（有些情绪不需要描写，一个动作就够了）

### 3.2 爽文需要"网感"

```
AI的"网感"：堆砌感叹号、滥用网络词汇、过度夸张
真人的网感：自然的吐槽、恰到好处的节奏打乱、跟读者"交互感"
```

判断标准：这个表达在龙空/贴吧/读者群里会有人说吗？如果太"规矩"了，就不够网感。

### 3.3 战斗场景的去AI味

**AI战斗**：招式名→对方反应→伤害描述→下一招，每步均匀分布
**真人战斗**：节奏跳跃——快时只用3个字写三招，慢时100字写一招前的对峙

```
AI战斗（均匀节奏）：
林夜一剑刺向赵明（8字）。赵明侧身闪开，反手一刀（8字）。林夜后退一步（5字）。

真人战斗（跳跃节奏）：
林夜出剑。一剑，两剑，三剑——赵明全部挡住。第四剑停在空中，不动了。
（前三招挤在8个字里 / 第四招单独100字写对峙 / 节奏跳跃才是真人的战斗感）
```

## 四、每10章风格自审

### 随机抽样检查

- 随机抽取本章+第X-5章+第X-10章各300字
- 排列在一起读
- 问自己：这三段读起来像同一个人在不同的时刻写的吗？还是像同一个模板换了词？

### 趋势追踪

| 检查项 | 前期(1-10) | 中期(50-60) | 后期(90-100) |
|--------|-----------|-----------|-------------|
| 平均句长 | __字 | __字 | __字 |
| 高频过渡词频率 | __次/千字 | __次/千字 | __次/千字 |
| 主要人物语气可区分度 | ✅/⚠️ | ✅/⚠️ | ✅/⚠️ |
| 战斗描写节奏变化 | ✅/⚠️ | ✅/⚠️ | ✅/⚠️ |

## v3 阶段 B 一次过 vs 重写判断矩阵

> **v3 标记**：本章与 `3-stage-tdd.md` 阶段 B 的"异常路径"对齐。提供给主代理 agent 的判断依据。

### 失败模式处理表

| 失败模式 | 是否可局部改 | 必须整章重写 |
|---|---|---|
| 红线单条命中 1 次 | ✓ | |
| 红线单条命中 ≥3 次 | | ✓ |
| 硬性 Grep 命中 ≤3 处/章 | ✓ | |
| 硬性 Grep 命中 >3 处/章 | | ✓ |
| 软性疑点（朗读不自然）| ✓ 列出疑点 → 人审 | |
| 设定漂移（人名/境界/物品冲突）| ✓ 修订相关段落 | |
| 伏笔操作错（埋/收标错）| ✓ 修订相关段落 | |
| 全文段式重复（连续 5 句同结构）| | ✓ |

### 重写触发逻辑

```
if 任意失败模式命中 "必须整章重写" 列:
    整章丢弃 → 重派子代理（带新压缩包）
elif 任意失败模式命中 "可局部改" 列:
    局部修订 → 重跑阶段 B
else:  # 软性疑点
    列入"系统疑点" → 进阶段 C 由人审决断
```

### 重写时的压缩包微调

如需重写，可微调压缩包以避免相同失败：

- 前情叙事加更具体的"近期剧情"段（避免子代理假设前情）
- 风格要求加"避免 X 句式"（针对具体失败）
- 词条快照加更严格的人物 ID（避免子代理混用）
