# 知识提取操作指南

## 使用路由

- 写前查询读“一、知识库可查询结构”和“写前查询包”。
- 写后提案读“三、提取报告格式”和“四、人工审核”。
- 入库执行读“五、人审入库与写入执行”；禁止跳过人审。
- 决策日志只在触发五类重大方向变更时读“七、决策日志触发”。

## 核心理念

知识提取是将 raw 文本中的信息提炼为结构化知识的过程。知识库是**可查询的 markdown 文件系统**——AI 通过 Grep/Read 精准检索，而非逐篇全文阅读。`知识库/` 是正史；`知识库/暂存区/` 只存待确认的变更提案。

**双向流动**：
```
创作产生 raw 信息 → 提取结构化事实 → 写入知识库
   ← Grep 查询知识库，提供准确上下文 ←
```

**核心原则**：AI 只提变更提案，人做最终决策。禁止无人审入库；任何正式词条、`_index.md`、决策日志变更都必须经过人审入库。

## 一、知识库可查询结构

### 文件布局

```
知识库/
├── _index.md          ← 全局索引（Grep 快速扫描）
├── 人物/
│   ├── 林夜.md
│   └── ...
├── 地点/
├── 势力/
├── 物品/
├── 概念/
└── 暂存区/
```

### 关键设计：Grep 可查询字段

每个词条的**结构化字段使用固定格式**，确保 Grep 直接命中：

```
**字段名**：值
```

例如：
- `**境界**：剑宗` → `Grep "\*\*境界\*\*" 知识库/人物/` 可查出所有人境界
- `**位置**：天剑宗` → `Grep "\*\*位置\*\*：天剑宗" 知识库/` 可查出谁在此地
- `**与主角关系**：盟友` → `Grep "\*\*与主角关系\*\*：盟友" 知识库/势力/` 查所有盟友

### 规范化表格字段

关键关系表和出场记录表使用固定列名，方便读取：
- `| 人物 | 关系类型 | 数值 | 最后变化章 |`
- `| 章节 | 关键事件 | 境界变化 | 关系变化 |`
- `| 章节 | 事件 | 实力变化 |`

## 二、写作前查询（写前注入）

novel-write 步骤②：写新章之前，必须查询知识库获取当前状态。

### 查询流程

1. 从细纲获取本章关联词条列表
2. **先查 `_index.md`**：Read 全局索引，获取全局概览
3. **再查具体词条**：对每个关联词条，Read 其"当前状态"段和"关键关系"表
4. **查暂存区**：只读取与本章关联词条同名或同 ID 的待确认提案，并在压缩包里标注"未入正史"
5. **读追踪层**：读取 `追踪/当前上下文.md`、`追踪/伏笔.md`、`追踪/时间线.md`、`追踪/角色状态.md`、`追踪/情节线.md`、`追踪/写作任务.md`，只提取与本章相关的当前状态
6. **拼接上下文简报**：

```markdown
# 第X章 上下文简报

## 本章关联实体当前状态
（从 _index.md + 各词条"当前状态"段提取）

| 词条ID | 实体 | 类型 | 关键字段 | 最新变化 |
|--------|------|------|---------|---------|
| CHAR-001 | 林夜 | 人物 | 境界：剑宗 / 位置：天剑宗 | 第20章：剑冢悟道突破 |
| CHAR-002 | 苏瑶 | 人物 | 境界：剑者 / 与林夜：♡4 | 第18章：发现林夜秘密 |
| LOC-001 | 剑冢 | 地点 | 所属：天剑宗后山 | 第15章：首次提及 |

## 本章相关伏笔
（从 追踪/伏笔.md Grep 本章编号）
| 编号 | 内容 | 状态 | 计划回收 |
|------|------|------|---------|
| F008 | 剑气在剑冢异常活跃 | 已暗示2次 | 第25章 |

## 本章追踪状态
（从 追踪/当前上下文.md、追踪/时间线.md、追踪/角色状态.md 提取）
| 类型 | 当前状态 | 本章风险 |
|------|---------|---------|
| 当前上下文 | 第X章开场接上一章码头冲突 | 不要跳过追兵压力 |
| 时间线 | 入宗前第七日夜 | 船行时间需合理 |
| 角色状态 | 林夜位置：望海镇码头 | 不得忽然回到客栈 |
| 情节线 | PL-001 主线逃亡：推进中 | 本章必须推进逃亡压力 |
| 写作任务 | WT-001：self_checked | 等待作者终审 |

## 前3章摘要
（从 摘要/ 读取）
...
```

### 标准 Grep 查询模式

| 目标 | Grep 命令 |
|------|----------|
| 某人物当前境界 | `Grep "\*\*境界\*\*" 知识库/人物/林夜.md` |
| 谁在某个位置 | `Grep "\*\*位置\*\*：天剑宗" 知识库/人物/` |
| 某势力的盟友 | `Grep "盟友" 知识库/势力/血魔宗.md` |
| 某人的所有关系 | Read 知识库/人物/林夜.md 中"关键关系"表 |
| 最近章的变化 | Read 知识库/人物/林夜.md 中"出场记录"表最后3行 |
| 全局人物状态 | Read 知识库/_index.md 中"人物索引"表 |
| 某伏笔状态 | `Grep "F008" 追踪/伏笔.md` |
| 本章追踪状态 | Read `追踪/当前上下文.md`、`追踪/时间线.md`、`追踪/角色状态.md`、`追踪/情节线.md`、`追踪/写作任务.md` |

## 三、写作后提取

### 提取时机
- 每章人审通过后立即提取
- 重大修改后重新提取
- 每10章做一次 `_index.md` 同步检查

### 提取方法

不是"读完整篇文章然后凭记忆判断"。而是**对照细纲中标注的"知识库更新"标记，逐条对比**：

1. 细纲中标记了 `知识库更新：林夜境界变化` → 读取词条当前 `**境界**` 值 → 对比本章实际描述 → 生成更新提案
2. 细纲中标记了 `知识库更新：苏瑶好感度+1` → 读取词条当前关系数值 → 生成数值变更提案
3. 本章涉及了新的地点/势力/物品 → 生成新词条创建提案
4. 检查本章描述与词条"当前状态"是否矛盾 → 生成冲突报告
5. 对照细纲 `追踪更新`，生成追踪更新建议：`追踪/当前上下文.md`、`追踪/伏笔.md`、`追踪/时间线.md`、`追踪/角色状态.md`、`追踪/情节线.md`、`追踪/写作任务.md`

### 提取报告格式（写后变更提案）

```markdown
## 第X章 知识提取报告 / 写后变更提案

### ✅ 新事实
| # | 目标词条 | 字段 | 新事实 | 出处 |
|---|---------|------|--------|------|
| 1 | {{林夜}} | 背景 | 父亲在血魔域失踪三年 | 与剑尘对话段落 |

### ✏️ 修正建议
| # | 目标词条 | 字段 | 旧值 | 新值 | 出处 |
|---|---------|------|------|------|------|
| 2 | {{林夜}} | 标志特征 | 幼年遇袭 | 父亲所划 | 回忆段落 |

### 📊 数值变更
| # | 目标词条 | 字段 | 旧值 | 新值 |
|---|---------|------|------|------|
| 3 | {{林夜}} | **境界** | 剑灵 | 剑宗 |
| 4 | {{林夜}} | 关系-苏瑶 | ♡3 | ♡4 |

### ⚠️ 疑似冲突
| # | 字段 | 旧记录 | 本章描写 | 需人判断 |
|---|------|--------|---------|---------|
| 5 | 饮酒习惯 | 第3章"从不喝酒" | 第X章"端起酒杯" | 性格变化？ |

### 💡 伏笔线索
| # | 线索 | 可能方向 |
|---|------|---------|
| 6 | 剑气异常 | 剑冢与剑碑有关联 |

### 🧭 追踪更新建议
| 文件 | 更新内容 | 是否需要人审 |
|------|----------|--------------|
| 追踪/当前上下文.md | 当前焦点改为第X+1章船舱冲突 | 是 |
| 追踪/伏笔.md | F008 最近触发章更新为第X章 | 是 |
| 追踪/时间线.md | 新增"入宗前第七日夜，林夜登船" | 是 |
| 追踪/角色状态.md | 林夜位置更新为离开望海镇 | 是 |
| 追踪/情节线.md | PL-001 章节绑定新增第X章推进 | 是 |
| 追踪/写作任务.md | WT-001 状态从 human_review 改为 finalized；知识库处理完成后再单独改为 kb_reviewed | 是 |
```

报告先写入 `知识库/暂存区/章X-知识变更提案.md`，等待人审。不要直接改正式词条。

## 四、人工审核

```markdown
## 第X章 知识提取审核

请逐条回复：`条目号-操作`
操作：通过 / 拒绝 / 修改：[新内容] / 暂存

快捷示例：`1-通过，2-修改：父亲为保护他，3-4通过，5-性格变化不是冲突`
```

| 操作 | 含义 |
|------|------|
| **通过** | 按提取内容写入词条，并同步 `_index.md` |
| **拒绝** | 丢弃 |
| **修改** | 按人修内容写入 |
| **暂存** | 放入暂存区，等更多证据 |

---

## 五、人审入库与写入执行

通过的条目才能写入词条：
1. 更新"当前状态"段中对应 `**字段**` 值
2. 在"出场记录"表中新增一行
3. 在"事实演进"表中新增记录
4. 更新词条顶部 `> 最后更新：第X章`
5. 更新 `_index.md` 中对应行

拒绝的条目 → 丢弃。

暂存的条目 → 留在 `知识库/暂存区/条目名.md`，下次写前查询可提示但必须标注"未入正史"。

追踪更新 → 按人审意见写入 `追踪/当前上下文.md`、`追踪/伏笔.md`、`追踪/时间线.md`、`追踪/角色状态.md`、`追踪/情节线.md`、`追踪/写作任务.md`。如果追踪更新会改变正史判断，必须同步生成知识库变更提案，不得只改追踪文件绕过人审。

门禁更新 → 知识库提案和追踪更新都经作者处理后，才能建议 `workflow_gates.chapters.<场景任务ID>.knowledge_reviewed = true`。若作者暂存关键提案，写 `blocked_reason` 并保持该门禁未完成。

## 六、_index.md 同步

每10章同步一次全局索引：
- Read 所有词条的"当前状态"段
- 更新 `_index.md` 中对应行的关键字段
- 确保索引与词条一致

## 七、注意事项

### 要做的
- 查询时优先用 `Grep` 而非全文 Read（减少上下文消耗）
- 知识提取对照细纲标记，逐条对比而非全文盲扫
- 冲突必须上报（不自行判断）
- 双向更新（A的关系变了，B的词条也要同步）

## 决策日志提取

每章完成后检查是否触发了以下五类**必记决策**（模板匹配，不靠AI"感觉"）：

| 触发条件 | 示例 |
|---------|------|
| 人物生死/CP 配对变动 | "林夜不杀赵明，留为后续盟友" |
| 伏笔方向二选一 | "选择揭示剑冢秘密而非继续隐藏" |
| 新设定增补（突破原有世界规则） | "首次引入'剑域'概念——之前世界设定中不存在" |
| 跨地图衔接 | "地图 2 末尾钩子改为 X" |
| 普通行文选择 | 不记 |

提取后写入 `知识库/决策/决策日志.md`。

### 不要做的
- 不要逐篇全文阅读词条（查索引 + Grep 就够了）
- 不要猜测（不确定就标记）
- 不要在无人审确认的情况下修改词条

## v3 决策日志触发规则

> **v3 标记**：与 `assets/decision-log-template.md` 联动。仅匹配下列规则的决策才记入日志。普通行文选择不记。

### 触发条件与对应模板

| 触发条件 | 对应模板 | 示例 |
|---|---|---|
| **人物生死** | decision-log 模板规则 1 | "第 23 章林夜父母之死确认" |
| **CP 配对变动** | decision-log 模板规则 1 | "林夜 × 苏婉儿 配对确认" |
| **伏笔方向二选一** | decision-log 模板规则 2 | "F08 玄清夺舍 vs 离开，选夺舍" |
| **新设定增补** | decision-log 模板规则 3 | "新增长老境界：化神" |
| **跨地图衔接** | decision-log 模板规则 4 | "地图 2 末尾钩子改为 X" |
| **人物弧光重大转折**（可选） | decision-log 模板规则 5 | "林夜从隐忍冷静 → 偏激冲动" |

### 提取流程（v3 阶段 C 人审定稿后）

1. **扫描本章**：对照细纲标记 → 识别新实体 / 状态变化 / 重大决定
2. **匹配触发**：5 类硬触发 + 1 类可选触发中匹配几条
3. **生成草稿**：每条触发对应 1 个决策日志条目（暂存区）
4. **人审**：用户确认 → 入库 + 更新 `_index.md`
5. **决策日志触发**：使用 `assets/decision-log-template.md` 的格式，写入项目内 `知识库/决策/决策日志.md`（普通行文选择跳过）

### 不写决策日志的反例

- 普通对话风格选择（口语化 vs 文言）
- 单章人物对话长短调整
- 风景描写详细程度
- 修辞偏好（明示 vs 暗示）

这些属于"作者偏好迭代"，不是"决策"。
