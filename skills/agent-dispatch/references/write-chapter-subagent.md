# 模式 1：章节起草子代理

> 配合 `SKILL.md` §5 模式 1 入口路由使用。
> 单 subagent + 上下文压缩包，输出章节草稿 + 摘要 + 标题方案。
> 主要被 novel-write 步骤③ 调用。

---

## 1. 入口与适用范围

入口触发：
- novel-write 步骤③ 调用子代理起草章节（程序内部）
- 用户手动说"调度子代理起草章节"时，必须先通过 novel-write 调用前自检，再进入本模式

适用：起草 1 章正文草稿（约 3000-5000 字），需 4 段式子代理（上下文隔离模式）+ 完整压缩包。是否定稿由作者在 novel-write 阶段 C 决定。本模式不能绕过 `情节线ID`、`场景任务ID` 与 `workflow_gates.chapters` 门禁。

---

## 2. 详细流程

### 步骤① 子代理上下文压缩包生成

- 读 novel-write 已确认的目标章节与 `追踪/写作任务.md` 的 `场景任务ID` → 定位本章细纲；`current_chapter` 只表示已定稿章节号
- 读 `workflow_gates.chapters.<场景任务ID>` → 确认本章已通过 `outline_ready` 门禁
- 读 novel-structure L3 reference 的 8 字段（核心事件 / 冲突 / 人物 / 爽点 / 节奏 / 伏笔 / 关联词条 / 钩子）
- 读前 3 章摘要 → 压缩为 ≤ 300 字前情叙事
- 先读 `知识库/_index.md`，再按关联词条读取正式词条；Grep `**境界**` `**位置**` `**关系**` 等关键字段 → 词条快照
- 读取相关 `知识库/暂存区/` 提案 → 标注"未入正史"，只作提醒，不作为确定设定
- 读取追踪层：`追踪/当前上下文.md`、`追踪/伏笔.md`、`追踪/时间线.md`、`追踪/角色状态.md`、`追踪/情节线.md`、`追踪/写作任务.md` → 本章续写提醒
- 从项目根 `novel-config.json` 读用户画像 / 风格 → 风格要求

### 步骤② system prompt + user prompt 构造

- system prompt：固定部分（角色 + 12 条铁律 + 字数限制）
- user prompt：细纲 + 压缩包 + 起草任务

### 步骤③ 子代理执行 + 输出

- 调用当前平台真实可用的子代理机制（隔离上下文）；若平台不支持子代理，则主代理顺序执行并标注"未使用子代理隔离"
- 接收章节草稿 + 摘要 + 2-3 标题方案
- 不调用工具（除非 system prompt 显式允许）

### 步骤④ 失败处理

- 子代理超时 → 重派（首次）；2 次失败 → 简化压缩包 → 重派
- 子代理输出格式错 → 不修改 → 重派
- 子代理产出违反铁律 → 拒绝 → 重新起草

---

## 3. 输入输出契约

**输入**：
- 细纲（8 字段）
- 上下文压缩包（前情叙事 / 词条快照 / 暂存提案提醒 / 当前上下文 / 伏笔 / 时间线 / 角色状态 / 情节线 / 写作任务 / 风格）
- 项目根 `novel-config.json`

**输出**：
- 章节草稿（按字数限制）
- 章节摘要（1 段）
- 2-3 章节标题方案
- 不引入压缩包外的设定

---

## 4. 失败处理

| 失败模式 | 处理 |
|---|---|
| 子代理超时 | 重派（首次）；2 次失败 → 简化压缩包 → 重派 |
| 输出格式错 | 不修改 → 重派 |
| 违反铁律 | 拒绝 → 重新起草 |
| 3 次失败 | 暂停起草，提交问题给作者决定是否改细纲、改风格或人工写作 |

## 5. 反模式

- ❌ **子代理读整个项目**：上下文膨胀 → 子代理注意力分散
- ❌ **压缩包 > 1000 字**：失去"压缩"意义
- ❌ **跳过细纲直接给灵感**：子代理输出不可控
- ❌ **让子代理读 tools**：除非显式允许，否则不调用
- ❌ **多次重派相同输入**：2 次失败必须改输入（简化压缩包或调整 system prompt）
