# 模式 2：并行审核子代理

> 配合 `SKILL.md` §5 模式 2 入口路由使用。
> 4 视角并行子代理，输出 4 视角独立报告 → 主代理合并。
> 主要被 novel-meta M4 步骤② 调用。

---

## 1. 入口与适用范围

入口触发：
- novel-meta M4 步骤② 派 4 视角子代理（程序内部）
- 用户手动说"调度 4 视角并行审计"（少用）

适用：审计 1 个 skill 的合规性 / 配置一致 / 模板对齐 / 触发器一致性。

---

## 2. 详细流程

### 步骤① 目标识别

- 用户说"审计 novel-X" → 确定目标 skill
- 读取 SKILL.md + skill 的 `references/`
- 读取项目状态（如《丹眼因果》前 N 章摘要）

### 步骤② 4 视角并行派发

- 派 4 个独立子代理：
  - **视角 1：流程合规** — 对照 SKILL.md 步骤 vs 实际执行
  - **视角 2：配置一致** — 项目根 `novel-config.json` 字段是否被 skill 读 + 是否对齐
  - **视角 3：模板对齐** — skill 引用的 reference 与 assets/ 模板一致
  - **视角 4：触发器** — `进度.json.triggers` 与 SKILL.md 触发器描述一致

### 步骤③ 子代理只读不写

- 4 子代理**只读**目标文件
- 不调用 Write/Edit
- 不修改任何文件（read-only contract）

### 步骤④ 主代理合并报告

- 收集 4 视角输出
- 写 `docs/reviews/<date>-<skill>-audit.md`
- 报告含：合规率（4 维度各 1）/ 漂移项清单 / 建议修改（含 必修/选修/允许 分类）
- 触发后续：人审 → 决定走 M1/M2/M3 处置

---

## 3. 输入输出契约

**输入**：
- 目标 skill（novel-X）
- skill 的 SKILL.md
- skill 的参考项目状态（如《丹眼因果》前 N 章）

**输出**：
- 4 视角独立报告（合规率 / 漂移项 / 建议）
- 主代理合并为统一审计报告

---

## 4. 失败处理

| 失败模式 | 处理 |
|---|---|
| 1 子代理超时 | 该视角报告标"TIMEOUT"，其他 3 视角正常 |
| 2+ 子代理超时 | 重派超时的子代理；合并报告标"部分超时" |
| 4 子代理全超时 | 不生成报告，主代理标"AUDIT_FAILED" |
| 4 视角结论冲突 | 主代理按最严格意见生成报告基线，交用户裁决 |

## 5. 反模式

- ❌ **子代理可写文件**：read-only 契约破坏
- ❌ **单子代理 4 视角顺序执行**：失去"并行"意义
- ❌ **合并报告只取平均**：应裁决而非平均
- ❌ **4 视角审视同一文件但视角定义重复**：4 视角必须有不同焦点
- ❌ **审计 agent-dispatch 自身**：避免递归
