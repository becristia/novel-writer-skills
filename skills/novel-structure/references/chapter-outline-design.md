# L3 细纲规划 4 段式

> 配合 `SKILL.md` §5 Layer 3 入口路由使用。
> 设计每章细纲的 8 字段：核心事件/冲突/人物/爽点/节奏/伏笔/关联词条/钩子。

## 使用路由

- 新做细纲时读“4 段式子流程”和“模块特定模板”。
- 修改单章时读“章节元数据”和“8 字段”对位表。
- 写作前排查时读 validation 与反模式，不重读全部示例。

---

## 1. 入口与适用范围

入口触发：
- `"做细纲"` / `"加新章"` / `"修改细纲"`  （需 L2 已完成）

L3 依赖 L2 地图规划。

每章必须包含两部分：
- 8 字段：交给 novel-write 起草正文。
- 章节元数据：交给知识库、追踪系统和周期复盘定位状态。
- 矩阵绑定：交给 `追踪/情节线.md` 和 `追踪/写作任务.md` 维护长篇推进。

---

## 2. 4 段式子流程

### 步骤① brainstorming

8 字段 prompt：
- 核心事件（该章 1 个核心事件）
- 冲突类型+双方（谁 vs 谁、为何冲突）
- 人物动态（主要人物状态变化）
- 爽点类型+强度（升级/打脸/揭秘/情感共鸣，强度 1-5）
- 节奏标签（铺垫 / 冲突 / 高潮 / 收尾 / 日常）
- 伏笔操作（埋 / 收 / 无关 + 对应编号）
- 关联词条（涉及的人物/地点/物品；优先写 `词条ID`，可附词条名；必须可解析到 `知识库/_index.md` 或具体词条）
- 结尾钩子（章末抛向下一章的悬念）

章节元数据 prompt：
- POV（视角人物；默认主角有限视角，群像章必须标明主视角）
- 场景地点（本章主要地点；必须能对齐地点词条或待建词条）
- 故事时间（相对时间或明确日期，如"入宗第七日夜"）
- 出场人物（主场/配角/提及三类）
- 知识库更新标记（本章预计会新增/修改哪些词条字段；无则写"无"）
- 追踪更新（本章会影响 `追踪/伏笔.md`、`追踪/时间线.md`、`追踪/角色状态.md` 的哪些行）
- 情节线ID（如 PL-001；主线/支线/人物弧光/关系线/伏笔线）
- 场景任务ID（如 WT-001；对应 `追踪/写作任务.md`）
- 任务状态（planned；后续由 novel-write 按单步状态推进到 drafting、self_checked、human_review、finalized、kb_reviewed）

### 步骤② spec

写 `03-大纲/0X-地图X-细纲.md`（每章 1 个 8 字段条目）：

```
### 第 N 章：<标题>

#### 章节元数据

| 字段 | 值 |
|---|---|
| POV | 林夜 |
| 场景地点 | 望海镇东市 / 码头 |
| 故事时间 | 入宗前第七日夜 |
| 出场人物 | 主场：林夜；配角：玄清弟子；提及：玄冥剑主人 |
| 知识库更新标记 | 林夜位置变化；望海镇新增码头描述 |
| 追踪更新 | 伏笔 F015 强化；时间线新增逃亡节点；角色状态更新林夜位置 |
| 情节线ID | PL-001 主线逃亡 / PL-004 玄冥剑伏笔线 |
| 场景任务ID | WT-001 |
| 任务状态 | planned |

#### 8 字段细纲

| 字段 | 值 |
|---|---|
| 核心事件 | ... |
| 冲突类型+双方 | ... |
| 人物动态 | ... |
| 爽点 | 类型：升级，强度：4 |
| 节奏标签 | 高潮 |
| 伏笔操作 | 埋 F15 玄冥剑来历 |
| 关联词条 | CHAR-001 林夜 / LOC-001 望海镇 / FAC-001 玄清 |
| 结尾钩子 | ... |
```

### 步骤③ execution

写 spec → 人审 → 更新 `phases.structure.total_chapters_planned` 与 `追踪/写作任务.md` planned 行；`current_chapter` 只表示已定稿章节号，不在大纲阶段写入

### 步骤④ validation

- 跑 `validate_novel_structure_skill.py --template l3-chapter-outline`（自身）
- 8 字段完整性 grep（每章 8 字段齐全）
- 关联词条解析检查：每个词条ID或词条名能在 `_index.md` 或 `知识库/<类型>/` 找到；缺词条时不得跳过，回 novel-design 补设定或由作者确认标记为待建词条
- 章节元数据检查：POV / 场景地点 / 故事时间 / 出场人物 / 知识库更新标记 / 追踪更新齐全
- 矩阵绑定检查：情节线ID 可在 `追踪/情节线.md` 找到或新增提案；场景任务ID 可在 `追踪/写作任务.md` 找到或新增 planned 行
- 节奏密度自检：每 10 章 ≤ 3 大场景 / 每场景 ≥ 3 章 / 每 10 章 ≥ 1 章日常 / 每地图 ≤ 3-4 核心事件
- 8 字段与 novel-write §5 阶段 ① 字段对位（**关键跨 skill 契约**）
- 跑 `validate_novel_structure_skill.py --template pacing-check`

## 3. 模块特定模板

`03-大纲/0X-地图X-细纲.md` 字段速查（与 novel-write 阶段 ① 必填 8 字段对位）：

### 章节元数据

| 字段 | 下游用途 |
|---|---|
| POV | 控制视角与口吻，避免一章内视角乱跳 |
| 场景地点 | 写前查询地点词条，写后同步时间线 |
| 故事时间 | 检查时间线、角色移动和年龄/修炼周期 |
| 出场人物 | 生成角色状态快照和关系线提醒 |
| 知识库更新标记 | 指导写后知识提取，不靠 AI 盲扫全文 |
| 追踪更新 | 指导 `追踪/伏笔.md`、`追踪/时间线.md`、`追踪/角色状态.md` 的待更新项 |
| 情节线ID | 绑定 `追踪/情节线.md`，防止主线/支线/人物弧光断线 |
| 场景任务ID | 绑定 `追踪/写作任务.md`，让 novel-write 能定位任务状态 |
| 任务状态 | 初始为 planned，后续由 `workflow_gates.chapters.<场景任务ID>` 和 novel-write 推进 |

### 8 字段

| 字段 | novel-write 阶段 ① 对位 |
|---|---|
| 核心事件 | 核心事件 |
| 冲突类型+双方 | 冲突 |
| 人物动态 | 人物动态 |
| 爽点 | 爽点 |
| 节奏标签 | 节奏标签 |
| 伏笔操作 | 伏笔操作 |
| 关联词条 | 关联词条（优先词条ID） |
| 结尾钩子 | 结尾钩子 |

## 4. 衔接

- 上游：L2 地图规划（地图 X 名称）
- 下游：novel-write 阶段 ① 读本章细纲
- 平行：novel-design 知识库/（人物/地点/物品 通过关联词条引用）

## 5. 反模式

- ❌ **先于 L2 设计细纲**：细纲依赖地图
- ❌ **8 字段不全**：缺任一字段 → novel-write 阶段 A 红灯
- ❌ **章节元数据缺失**：没写 POV/时间/地点/人物 → 写作压缩包无法判断当前状态
- ❌ **情节线ID 缺失**：章节推进了人物弧光或伏笔线却不挂线 → 50章后必断
- ❌ **场景任务ID 缺失**：无法知道该章是 planned、drafting、self_checked 还是 human_review
- ❌ **8 字段与 novel-write 阶段 ① 不一致**：字段名/类型不匹配 → 跨 sub-project 契约失败
- ❌ **节奏标签单一**：全章标"高潮"或全标"日常" → 节奏崩盘
- ❌ **爽点强度过载**：每章 5 强度爽点 → 读者疲劳
- ❌ **末尾钩子缺失**：章间无衔接 → 章节脱节
- ❌ **关联词条遗漏**：本章涉及人物/地点未在关联词条列 → novel-write 压缩包缺失
- ❌ **关联词条不可解析**：写了词条名但知识库找不到 → novel-write 写前查询包会缺设定
